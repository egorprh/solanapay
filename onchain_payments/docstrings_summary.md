# Docstrings Summary для OnChain Payments Service

## Обзор

Все методы и классы в проекте OnChain Payments Service теперь имеют подробные docstrings в формате Google/NumPy style. Это значительно улучшает читаемость кода, обеспечивает встроенную документацию и поддерживает автоматическую генерацию документации.

## Стандарт документации

Используется формат Google-style docstrings с следующими секциями:
- **Краткое описание** - одна строка с описанием назначения
- **Подробное описание** - расширенное объяснение функциональности
- **Args** - описание параметров с типами
- **Returns** - описание возвращаемых значений
- **Raises** - возможные исключения
- **Example** - примеры использования
- **Note** - дополнительные примечания

## Обновленные файлы

### 1. `handlers.py` - Обработчики NATS сообщений

#### `handle_payment_info_request(msg: Msg) -> None`
- **Назначение**: Обработка запроса на получение информации о платеже
- **Функциональность**: Извлекает payment_id, обрабатывает платеж, отправляет ответ
- **Примеры**: Показаны ожидаемые данные запроса и формат ответа

#### `handle_payment_creation_request(msg: Msg) -> None`
- **Назначение**: Обработка запроса на создание нового платежа
- **Функциональность**: Создает платеж, выделяет кошелек, сохраняет в БД
- **Примеры**: Демонстрирует создание платежа с параметрами сети и токена

#### `handle_payment_cancellation_request(msg: Msg) -> None`
- **Назначение**: Обработка запроса на отмену платежа
- **Функциональность**: Отменяет платеж, освобождает кошелек
- **Примеры**: Показывает процесс отмены и обновления статуса

### 2. `logic/utils.py` - Утилитарные функции

#### `Utils` (класс)
- **Назначение**: Утилитарный класс для работы с внешними API
- **Функциональность**: Получение цен токенов, маппинг идентификаторов

#### `get_token_price(token_str: str, network_str: str) -> float`
- **Назначение**: Получение актуальной цены токена через CoinGecko API
- **Функциональность**: Асинхронный запрос к CoinGecko, поддержка основных токенов
- **Примеры**: Демонстрирует получение цены ETH
- **Примечания**: Ограничения API, рекомендации по использованию ключей

#### `_get_coingecko_token_id(token: str, network: str) -> Optional[str]`
- **Назначение**: Маппинг токенов на CoinGecko идентификаторы
- **Функциональность**: Внутренний метод для валидации токенов
- **Примеры**: Показывает маппинг для различных токенов и сетей

### 3. `logic/wallet_manager.py` - Менеджер кошельков

#### `WalletManager` (класс)
- **Назначение**: Управление пулом кошельков в различных сетях
- **Функциональность**: Выделение/освобождение кошельков, координация через Redis

#### `__init__() -> None`
- **Назначение**: Инициализация менеджера кошельков
- **Функциональность**: Создание подключения к Redis, настройка пула

#### `get_available_wallet(network: str) -> Optional[str]`
- **Назначение**: Получение доступного кошелька для сети
- **Функциональность**: Поиск свободного кошелька, блокировка в Redis
- **Примеры**: Демонстрирует получение кошелька для Ethereum
- **Примечания**: Объединение EVM-сетей в группу 'evm'

#### `release_wallet(network: str, address: str) -> None`
- **Назначение**: Освобождение кошелька для повторного использования
- **Функциональность**: Удаление блокировки из Redis
- **Примеры**: Показывает процесс освобождения кошелька

#### `close() -> None`
- **Назначение**: Корректное закрытие соединений с Redis
- **Функциональность**: Закрытие клиента и пула подключений
- **Примечания**: Важность вызова при завершении работы

### 4. `logic/payments.py` - Основная логика платежей

#### `erc20_abi_default() -> List[Dict[str, Any]]`
- **Назначение**: Получение стандартного ABI для ERC20 токенов
- **Функциональность**: Возвращает минимальный набор функций (balanceOf, decimals, transfer)
- **Примеры**: Показывает количество функций в ABI

#### `token_addresses_default() -> Dict[Network, Dict[Token, str]]`
- **Назначение**: Получение адресов токенов для различных сетей
- **Функциональность**: Маппинг токенов на контрактные адреса
- **Примечания**: Необходимость заполнения актуальными адресами

#### `Data` (класс)
- **Назначение**: Контейнер для статических данных блокчейн-сетей
- **Функциональность**: Единая точка доступа к ABI и адресам токенов

#### `Payments` (класс)
- **Назначение**: Основной класс для обработки криптовалютных платежей
- **Функциональность**: Создание, обработка, отмена платежей в различных сетях

#### `__init__() -> None`
- **Назначение**: Инициализация класса Payments
- **Функциональность**: Создание подключений к блокчейн-сетям, инициализация WalletManager

#### `create_payment(payment_id: str, payment_network: str, payment_token: str) -> Dict[str, Any]`
- **Назначение**: Создание нового платежа
- **Функциональность**: Выделение кошелька, фиксация баланса, сохранение в БД
- **Примеры**: Демонстрирует создание платежа с UUID
- **Примечания**: Автоматическая блокировка кошелька в Redis

#### `process_payment(payment_id: str) -> Dict[str, Any]`
- **Назначение**: Обработка платежа - проверка поступления средств
- **Функциональность**: Проверка баланса, обновление статуса, освобождение кошелька
- **Примечания**: Автоматическое вычисление эквивалента в USD

#### `cancel_payment(payment_id: str) -> Dict[str, Any]`
- **Назначение**: Отмена платежа
- **Функциональность**: Обновление статуса, освобождение кошелька

#### `_close_redis() -> None`
- **Назначение**: Закрытие соединения с Redis
- **Функциональность**: Корректное закрытие через WalletManager

### 5. `__main__.py` - Главная функция

#### `main() -> None`
- **Назначение**: Главная функция приложения OnChain Payments Service
- **Функциональность**: Инициализация NATS, подписка на сообщения, обработка запросов
- **Примеры**: Показывает запуск сервиса через asyncio.run()
- **Примечания**: Список NATS subjects, корректное закрытие соединений

### 6. `models/payment.py` - Модель данных

#### `Payment` (класс)
- **Назначение**: Модель данных для криптовалютного платежа
- **Функциональность**: Валидация данных, сериализация в JSON
- **Атрибуты**: Подробное описание всех полей модели
- **Примеры**: Демонстрирует создание экземпляра платежа

## Генерация документации

### 1. **Sphinx**
```bash
# Установка Sphinx
pip install sphinx sphinx-rtd-theme

# Генерация документации
sphinx-build -b html docs docs/_build/html
```

### 2. **pydoc**
```bash
# Генерация HTML документации
python -m pydoc -w onchain_payments.logic.payments

# Просмотр документации в браузере
python -m pydoc -p 8080
```

### 3. **IDE интеграция**
- VS Code: Автоматическое отображение docstrings при наведении
- PyCharm: Встроенная поддержка Google-style docstrings
- Jupyter: Отображение документации в ячейках
